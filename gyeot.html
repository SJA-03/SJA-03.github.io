Memory Agent.

01

핵심 문제

오늘 점심의 예외가 저녁까지 남을 수 있습니다.

평소 조용한 식당을 선호해도 오늘 점심만은 활기찬 곳을 원할 수 있습니다. 예외의 유효 기간을 놓치면 이후의 제안까지 달라집니다.

평소의 선호

조용한 식당

오늘 점심의 예외

활기찬 곳 · 점심 이후에는 종료

02

내 역할

평가 형식을 정리하고 여행 프로토타입을 만들었습니다.

내가 맡은 일

  • 대화 기억 평가의 공통 입출력 형식·시간 범위·기준 정리
  • 웹의 대화 기반 기억 추출·일정 제안 구현
  • 개인 iPhone 프로토타입의 기억 편집·제안 흐름 구현

팀 작업과 개인 작업

공통 형식은 팀의 대화 기억 평가를 위해 정리했습니다. 여행 웹·iPhone 프로토타입은 개인 확장 작업입니다. 모델 간 성능 비교는 아직 완료하지 않았습니다.

03

선택과 이유

선택이유

기억에 원문·사람·여행·기간을 저장

같은 말이라도 누구의 조건인지, 언제까지 적용할지 달라서

형식·범위가 맞지 않는 후보는 저장하지 않음

모델이 기간이나 대상을 잘못 추출한 내용을 그대로 쓰지 않도록

수정 이력과 일정 버전을 확인

사용자가 수정한 내용이나 이미 바뀐 일정을 덮어쓰지 않도록

04

결과와 검증

임시 조건이 남는 오류를 수정하고 다시 평가했습니다.

현재 확인한 범위

웹·iPhone 프로토타입 구현 · 일부 실기기 동작 확인

구현·확인한 것

  • 웹에서 모델 기억 추출·모의 지연에 따른 일정 제안
  • 실제 iPhone 설치·기억 동기화·타이머 알림 확인
  • 임시 조건 오류 수정 후 같은 합성 대화 재평가

후속 작업·검증

  • 새 대화·새 여행에서의 검증
  • 화면 꺼짐 상태의 실제 이동·외부망 연결
  • 반복 사용 시 제안 근거의 이해·수정 과정 확인

오류 수정은 기존 합성 대화로 확인했습니다. 새 대화에서의 정확도나 실제 예약 변경·전체 여행 최적화를 검증한 결과는 아닙니다.

05

배운 점

원문 근거가 있어도 모델이 “오늘만”이라는 조건을 평소의 선호로 잘못 저장할 수 있었습니다. 원문뿐 아니라 적용 기간이 맞는지도 검사해야 했습니다.

기술 세부 내용

웹·모바일·이동 중 판단의 차이

웹은 모델로 기억을 추출하고, 모바일은 온디바이스 모델과 규칙으로 후보를 만듭니다. 이동 중에는 미리 준비한 기억과 장소 후보를 사용하며, 사용자가 변경안을 확인한 뒤 반영합니다.

수정 이력과 오래된 정보 처리

기억을 수정하거나 적용을 해제하면 기존 내용을 지우지 않고 새 이력으로 남깁니다. 일정 변경 전에는 완료·고정 일정과의 충돌, 기억·일정 버전이 바뀌었는지도 확인합니다.

오래된 경로나 확인하지 못한 장소 정보는 조건을 충족한 것으로 처리하지 않습니다.
